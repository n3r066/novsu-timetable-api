# Групповой эфемерный бот команд (group_bot.py)

## Что это
Бот @novsutimetablebot отвечает в супергруппе «Чат расписание бот»
(NOVSU_GROUP_CHAT_ID) на слеш-команды расписания. Ответ — ЭФЕМЕРНЫЙ
(видит только автор команды) и копия поста/раздела из канала 1 в 1.

Команды: `/timetable` и `/расписание` — вся неделя; `/today` `/сегодня` —
сегодня; `/tomorrow` `/завтра` — завтра; `/opd` `/опд` — списки ОПД по
виртуальным группам (без аргумента — ближайшая дата с ОПД, обычно следующий
четверг; с аргументом `/opd завтра`, `/opd чт` — указанный день);
аргументы дней: `сегодня|завтра|вся|неделя|пн..вс`.

- `/timetable` → весь закреп канала 1 в 1 (`sendRichMessage`): шапка
  «НЕДЕЛЯ 4 · нижняя», счётчик пар, разделы живых дней с таблицами,
  ОПД-разделы и сворачиваемые «Скрин с портала». Скрины — готовые из кеша
  `state/dashboard_screens.json` (рендер ноль, парсинг ноль). Строка
  «Источники: …» из ОПД-раздела уходит (`_strip_sources`) — ссылки
  остаются только в закрепе канала. Если копия с полными составами ВГ
  не влезает в лимит эфемерных rich (~45 КБ), составы ужимаются в
  строчку «Вместе в ВГ N · X чел. · полные списки: /opd» — неделя уходит
  ОДНИМ сообщением, составы живут в `/opd`.
- `/today` и прочие дни → один раздел дня ровно как в закрепе: таблица
  «№ / занятие / место / время», ОПД по виртуальным группам и скрин дня.
- `/opd` → только ОПД-кусок из раздела дня канала, но чище: без «Источников»
  и без эмодзи. Шапка — настоящий rich-заголовок «ОПД · ПО ВИРТУАЛЬНЫМ
  ГРУППАМ · 24.09 · идут 7 из 27» (heading, раздел всегда раскрыт, свёрнутой
  обёртки нет); корпуса по числу идущих (крупные первыми, как в закрепе);
  внутри корпуса люди по кабинетам (`_opd_room_sort_key`: 106, 106хк, 216 —
  числом, суффикс следом; в одном кабинете раньше тот, кому к 14:00) —
  однокабинетники стоят рядом; составы «Вместе в ВГ» свёрнуты по умолчанию
  (внутри институты раскрыты — один клик до полной таблицы); «Занятий не
  будет» — rich-заголовок + таблица «ФИО · ВГ» в конце, видна без раскрытия.
  Кеш `state/opd_cache.json`; закреп канала при этом не меняется.
- Эфемерные rich-сообщения ограничены ~45 КБ (живьём 2026-09-23: 44,2 КБ
  уходит, 45,4 — «rich message must be non-empty»; обычным сообщениям лимит
  не мешает, закреп канала больше и работает). Двухступенчатая защита:
  неделя/день сначала ужимаются `_slim_mates` (составы ВГ → строчка со
  ссылкой на `/opd`, одно сообщение), при нехватке и этого `/opd` и прочие
  ответы режутся `_split_rich` на куски ≤ 43 КБ — несколько сообщений
  подряд, каждое своей привязкой к команде.
- Если rich-отправка не прошла — деградация до текстовой вырезки
  (шапка «СРЕДА · 23.09.2026 · 3 пары · 1 ДОТ» и пары строками).
  Текст тот же, картинок нет.
Дата всегда по Москве (сервер в UTC).

## Как устроена эфемерность (нативная, Bot API 10.2+/10.3)
Ответ уходит с `ephemeral_message_parameters.receiver_user_id` — его видит
только автор команды; Telegram сам прячет и сам удаляет со временем.
Проверено живьём 2026-09-23: sendMessage и sendRichMessage дают
`message_id: 0` + `ephemeral_message_id`, чужие клиенты ничего не видят.

- Бот — админ группы, поэтому отвечать можно в любой момент: без
  15-секундного окна и без `callback_query_id` (ограничение не-админов).
- Ответ привязан `reply_to_message_id` к самой команде: клиент паркует
  «беспризорную» эфемерку над последним сообщением, из-за чего она
  выглядела «пришедшей раньше» команды; с привязкой она вкладывается под
  команду как обычный ответ. Если команда уже удалена (Bad Request
  message to be replied not found) — ответ уходит повторно без привязки.
- Перед ответом бот выдерживает паузу `GROUP_BOT_ANSWER_DELAY_S`
  (env `NOVSU_GROUP_BOT_DELAY_S`, по умолчанию 1.5 c): ответ из кеша
  настолько быстр, что обгоняет подтверждение отправки команды клиента и
  рисуется над её сообщением; пауза даёт команде лечь первой.
- Кирилличные псевдонимы команд парсятся, но в меню группы видны только
  латинские (`is_ephemeral` принимает латиницу).
- Анонимный админ (from отсутствует) не имеет user_id для адресации —
  ему уходит обычный публичный ответ.
- Кирилличные псевдонимы (`/сегодня`) парсятся, но в меню не регистрируются:
  BotCommand допускает только латиницу. Команда при отправке видна группе,
  ответ всё равно эфемерный.
- Доставка эфемерного сообщения НЕ гарантирована (офлайн-клиент может не
  получить) — это куртиз, а не канал доставки.
- Страховка от регресса API: если ответ вдруг ушёл публично (message_id != 0
  и нет ephemeral_message_id) — бот мгновенно вытирает его deleteMessage
  и алертит хозяина в ЛС.
- На старте регистрирует команды группы (`setMyCommands`, scope chat,
  `is_ephemeral: true`): в меню видны только отправителю.

## Безопасность (только группа, только хозяин)
- Без `NOVSU_GROUP_CHAT_ID` процесс даже не стартует (fail-closed).
- Игнорируются: ЛС, чужие чаты, чужие пользователи.
- Разрешён `TG_DM_TARGET` и анонимный админ (from=None + sender_chat=чат).

## Где живёт и как управлять (systemd, первично)
Юнит `novsu-group-bot.service` (enabled, автозапуск при ребуте):
    systemctl status novsu-group-bot        # статус
    journalctl -u novsu-group-bot -f         # лог
    systemctl restart novsu-group-bot        # перезапуск
    systemctl disable --now novsu-group-bot  # ВЫКЛЮЧИТЬ слеш-команды
    systemctl enable --now novsu-group-bot   # ВКЛЮЧИТЬ обратно
Запасной вариант — tmux (не держать оба: getUpdates конфликт 409):
    cd /root/novsu-timetable-api && tmux new-session -d -s group-bot         "/usr/bin/python3 group_bot.py"
Перед ручным запуском: `ps aux | grep group_bot`.

## Отладка одним батчем
    /usr/bin/python3 group_bot.py --once

## Краш-алерты
3 неудачных поллинга подряд → ЛС хозяину; сбой sendMessage/sendRichMessage
или «эфемерность не сработала» → ЛС сразу.

## Связанные файлы
- `group_bot.py` — сам бот; `tests/test_group_bot.py` — тесты.
- `state/group_bot_offset.json` — оффсет getUpdates (не удалять без нужды).
- `state/last_parsed.json` — данные (пишет monitor).
- `state/dashboard_screens.json` — индекс готовых скринов закрепа.
- `state/last_dashboard_post.json` — штамп «Обновлено» для копии поста.
